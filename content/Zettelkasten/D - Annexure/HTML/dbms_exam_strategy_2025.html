Observed Patterns (2021–2025)
🔁Carbon-copy repetition: Q6a, Q6b, Q7a, Q7b, Q8 from 2021-22 are word-for-word repeated in 2022-23. This means ER mapping, BCNF definition, and the same universal relation normalization numerical (R={A,B,C,D,E,F,G,H,I,J}) are almost guaranteed.
📐RA + TRC is compulsory every year: Every paper has a multi-part relational algebra query on a given schema (Q3a or Q5a), followed by rewriting in TRC. This pattern is 4/4 years.
📊ER diagram design is always a full question: A 5-mark design question (draw ER with cardinality and participation) appeared in 2021-22, 2023-24 (NHL), and 2024-25 (team/players). Expect one in 2024-25 final too.
📈Normalization numericals are increasing in complexity: 2021-22 had simple 2NF→3NF; 2023-24 and 2024-25 add BCNF checking, dependency preservation, minima cover — 10-mark style multi-step.
🔀Module IV is expanding: Transaction/recovery questions were sparse in 2021-22 but became full 5-mark questions in 2023-24 and 2024-25. Write-ahead logging, timestamp ordering, schedule analysis are now standard.
📝Short notes (Q8) recycling: The same short note options — Anomalies, Data Independence, Transitive Dependency, De-Normalization — appear in both 2021-22 and 2022-23. Newer years introduce Data Fragmentation, Data Marts, Thomas's Write Rule.
🎯Q1 (compulsory) tests breadth: Designed to cover all 4 modules — usually 2–3 from Module I, 2 from Module II, 2–3 from Module III, 2 from Module IV. Studying the short-answer Q1 examples from all years is high leverage.
🆕Distributed DB / Data Warehouse trending up: Added as short notes in 2023-24 (Data Fragmentation, Data Marts) and as full questions in 2024-25 (Data Warehousing characteristics, Data Mining goals).
⚠️Never skip Module IV concurrency: Conflict serializability + precedence graph and timestamp ordering have appeared in 2023-24 and 2024-25 as 10-mark combined questions.
Strategy: In 3 hours with 60 marks (Q1 compulsory + any 5 from Q2–Q8), you need high precision on Tier 1 topics and selective depth on Tier 2.
TIER 1 — Very High Priority (must master)
RA queries + TRC rewriting
Practice writing 4–5 subqueries (select, project, join, set ops) on a given schema. Then rewrite each in Tuple Relational Calculus. Use schemas from past papers: MAILORDER, Passenger/Flight/Booking, Ships/Battles. Key operations: σ (select), π (project), ⋈ (join), ×, ∪, −, ρ. TRC format: {t | CONDITION}. Focus on join conditions and implicit existential quantifiers.
BCNF — definition, proof, decomposition
Memorize: A relation R is in BCNF if for every FD X→Y, X is a superkey. Know the two-attribute proof (any 2-attr relation is in BCNF). Practice checking and decomposing into BCNF. Compare with 3NF: every BCNF is 3NF, but not vice versa. 3NF allows non-trivial FDs where LHS is not superkey if RHS is prime attribute.
Normalization numerical (2NF → 3NF)
Solve the repeated question: R={A,B,C,D,E,F,G,H,I,J}, F={{A,B}→C, A→{D,E}, B→F, F→{G,H}, D→{I,J}}. Find key, identify partial and transitive dependencies, decompose step-by-step. Also practice BOOK relation and Doctor relation from past papers. Know how to find minima cover.
ER/EER → Relational mapping
Memorize all 7 steps of ER→relational mapping (regular entities, weak entities, binary 1:1, 1:N, M:N, multivalued attributes, n-ary). For EER: specialization/generalization — 3 options (single relation, multiple relations with superclass, multiple relations without superclass). Know tradeoffs of each EER mapping option.
TIER 2 — Medium Priority (aim for 3 of these)
Specialization Hierarchy vs Lattice
Hierarchy: subclass has exactly ONE superclass. Lattice: subclass can have MULTIPLE superclasses (shared subclass). Know how to identify user-defined vs attribute-defined, disjoint vs overlapping, total vs partial specializations. Draw example diagrams.
Schedule analysis (serial, recoverable, cascadeless, strict, conflict-serializable)
Practice precedence graph construction. Check each pair of conflicting operations. Cycle → not conflict serializable. Recoverable: if Ti reads from Tj, Tj commits before Ti. Cascadeless: only read committed data. Strict: no read/write until commit. Work through S3, S4, S5 from 2024-25 paper.
Recovery techniques (WAL, shadow paging, rollback)
Write-Ahead Logging: write log before data to disk. REDO (committed but not written), UNDO (written but not committed). Shadow paging: maintain current and shadow page tables — no log required but expensive. Thomas's Write Rule: skip obsolete write operations. Cascading rollback: why dangerous, how protocols prevent it.
Functional Dependencies: closure + minima cover
Attribute closure X⁺: start with X, apply FDs until no change. To find minima cover: (1) make RHS singleton, (2) remove redundant LHS attrs, (3) remove redundant FDs. Practice with G={AB→BC, D→E, BC→D, A→ADEBC} from 2023-24 Q5b.
EER schema design (draw ER diagram)
Practice drawing ER diagrams with: entity types, attributes (key, composite, multivalued, derived), relationship types (1:1, 1:N, M:N), weak entities, n-ary relationships, ISA hierarchies. For NHL/team questions: map requirements sentence-by-sentence to ER constructs. Always specify cardinality ratios and participation constraints.
Timestamp ordering protocol
Basic TO: compare read/write timestamps with transaction timestamp. Strict TO: delay until write-TS(X) ≤ ts(T). Thomas's Write Rule extension. Know when to abort vs wait. Compare with locking protocols: TO is deadlock-free but may cause cascading aborts.

Common Pitfalls & Confusions
BCNF vs 3NF confusion
Students often say BCNF = 3NF. Key difference: 3NF allows FD X→A where A is prime attribute (even if X is not superkey). BCNF requires X to be superkey in ALL cases. A relation can be in 3NF but not BCNF. Always check: is the LHS a superkey? If not, is the RHS a prime attribute?
RA syntax errors
Common mistakes: using wrong join condition (check shared attribute names), forgetting projection after join (get only needed columns), confusing natural join with theta join. In TRC: forgetting to bind all free variables, incorrect negation (∀ vs ∃). Always verify output schema matches expected result.
Conflating serializable types
Conflict serializable ≠ View serializable (VS is broader). Every conflict-serializable schedule is view-serializable, not vice versa. Precedence graph detects conflict-serializability only. A cycle means NOT conflict-serializable, but the schedule might still be view-serializable.
Hierarchy vs Lattice in EER
Hierarchy: each subclass has exactly one superclass. Lattice: a subclass can inherit from MULTIPLE superclasses (creates shared subclass). Disjoint vs Overlapping: disjoint = d in circle (entity can be in only one subclass); overlapping = o. Total vs Partial: total = double line (every entity must be in a subclass).
Physical vs Logical Data Independence
Physical: change internal/physical schema without affecting conceptual schema (e.g., change file organization). Logical: change conceptual schema without affecting external/view schema (e.g., add a new attribute). Logical independence is harder to achieve.
Lossless Join vs Dependency Preservation
Both are desirable decomposition properties but are SEPARATE. BCNF guarantees lossless join but NOT dependency preservation. 3NF guarantees both. In exam questions, check both separately. Lossless: R1 ⋈ R2 = R. Dependency preservation: every FD in F can be enforced in one relation without join.
